# Plan for #3: Tracer bullet: `concept add` and `concept list` through every seam

Approved by the human with all planner recommendations (open questions 1-10).

## Decisions
1. LABEL_TAKEN compares case-insensitively after whitespace normalisation (trim, collapse runs), against every prefLabel and altLabel of every Concept in hali:topics, same language.
2. Slugs keep Unicode alphanumerics: lowercase, non-alphanumeric runs -> `-`, trim `-`, `-2`/`-3` on collision.
3. Prefix table: hali writes the `# generated by hali` header and the 12 `@prefix` lines itself in spec §3.4 order, and strips the prelude oxttl emits (oxttl sorts prefixes by Reverse(len), trig.rs:908, so it cannot produce the spec order). A locked byte fixture guards this against oxttl upgrades.
4. Keep Clock/IdGen traits + deterministic impls + test-hooks env wiring here. HALI_TEST_NOW parsed by a small hand-written `YYYY-MM-DDTHH:MM:SSZ` parser (no date crate). Only cli reads HALI_TEST_*, only under cfg(feature = "test-hooks").
5. New rules, all exit 3: STORE_UNPARSEABLE, STORE_IO, CONFIG_INVALID.
6. Data dir created with mode 0700.
7. `concept add --broader/--alt` belong to #17.
8. Named graph IRIs: https://w3id.org/hali/graph/{core,vocabulary,resources,extensions}.
9. Usage errors (exit 2) keep clap's plain text under --json.
10. Language fallback deferred to #17: show only the prefLabel in the configured language.

## Contract
- Concept JSON record: `{"id":"machine-learning","label":"machine learning","alt_labels":[],"broader":[]}` (empty arrays always present).
- `concept add --json`: `{"schema_version":1,"concept":{...record...}}`, one compact line.
- `concept list --json`: `{"schema_version":1,"results":[...],"total":N,"truncated":bool,"next_offset":int|null}`; `--limit` (default 50), `--offset` (default 0); sorted by label (code point) then id; truncated = offset + len < total; next_offset = offset + len when truncated else null.
- `--json` is a global flag (before or after the subcommand).
- Text: `added concept <id> "<label>"`; list prints `<id>\t<label>` per line, nothing when empty; when truncated, stderr `note: showing <n> of <total>; next: --offset <k>`.
- Error envelope on stderr under --json: `{"schema_version":1,"error":{"rule","message","details","suggested_fix","suggested_command"}}` (details `{}` and suggested_command `null` when absent), stdout empty. Text mode: `error: <message>` and `hint: <suggested_fix>[ Try: <suggested_command>]`.
- LABEL_TAKEN (exit 1): message `label "machine learning"@en is already used by Concept machine-learning`; details `{"label","language","concept"}`; suggested_fix `Use the existing Concept, or choose a different label.`; suggested_command `hali concept list`; vocabulary.ttl byte-unchanged.
- Labels: trimmed/collapsed; empty, no letter/digit, or containing a control character -> usage error (exit 2).
- `hali:topics a skos:ConceptScheme` written to vocabulary.ttl on first `concept add`. Concept triples: `a skos:Concept ; skos:inScheme hali:topics ; skos:prefLabel "<label>"@<lang>`.
- Data dir: HALI_DATA_DIR (non-empty) > $XDG_DATA_HOME/hali (absolute) > $HOME/.local/share/hali. Reads never create anything; a missing dir is an empty store. Only changed files are written.
- Config: $XDG_CONFIG_HOME/hali/config.toml, `[vocabulary] language` only (default en); invalid TOML or BCP 47 tag -> exit 3 CONFIG_INVALID.
- STORE_UNPARSEABLE: any of vocabulary/resources/extensions.ttl fails to parse (incl. invalid UTF-8); details {file,line,column}; message must not echo file contents. STORE_IO: data dir unresolvable/unreadable/uncreatable; details {path}.
- Out of scope: --broader/--alt (#17), --dry-run (#8), locking/atomic publish (#5), SHACL (#7), hali schema (#6), --fields (#12), RDFC-1.0, concept show/rename/edit/remove (#17).
