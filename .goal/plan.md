Every test builds its tree in a sandbox under the system temp dir; when an ancestor of the sandbox holds an ignore file or a `.git` (the walk would honour it as a parent's), the test prints a NOTE and returns instead of failing falsely. Goal tests run as a non-root user for full strength; as root `unreadable` and `unreadable_ignore_file_reported` print a NOTE and assert the root-visible behaviour instead. Memory-capped tests (`ignore_file_device`, `huge_ignore_file_bounded`) re-run the test binary on `capped_child` as a child process with `RLIMIT_AS` set between fork and exec, because the limit is per process and would cap every other test if set in the test process.

`.goal/locked`: `tests/storage_walk.rs`.

## Approach

Implementer on opus (it touches guarded paths and the dependency; the rest of the feature is #22).

1. `Cargo.toml`: add exactly `ignore = "=0.4.34"` after `clap`, default features. Let cargo update `Cargo.lock` offline if possible (`cargo update -p ignore --precise 0.4.34` or a plain build); the lock must gain exactly `ignore` and `globset`.
2. `src/storage/walk.rs` (declared in `src/storage/mod.rs`): `WalkOptions`, `Walked`, `SkipReason`, `walk(root, &opts)`, built as in the issue's amended contract: the canonical root; `WalkBuilder` with `follow_links(false)`, the hidden/git/ignore switches, `parents(true)`, `require_git(true)`, `.haliignore`, `sort_by_file_name`, `OverrideBuilder` for user excludes, never `max_filesize`; a `filter_entry` that handles built-ins, the data dir (as given and canonicalized), non-UTF-8 names and, for a directory the crate is about to enter, the ignore-file check (`lstat` plus a bounded `O_NONBLOCK | O_NOFOLLOW` read, capped at 256 KiB with `{` nesting over 100 levels rejected, of `.gitignore`, `.ignore`, `.haliignore`, `.git/info/exclude` of a `.git` directory or symlink to one, and a `.git` file with its `commondir` and `<common>/info/exclude`; a `.git` that is a FIFO, a symlink to a file or dangling is rejected; a file whose matcher the crate then fails to build is rejected too, reported at the candidate file; a bad one is yielded as `bad_ignore_file` and the directory is not walked); the same check up front for the root and its parents (one `bad_ignore_file`, nothing walked; the crate's filter is not applied to the root). Symlinks: `canonicalize` (a permission error is `unreadable`, any other failure `not_regular`) then `metadata`; a directory is silent, outside the root `outside_root`, broken or non-regular `not_regular`, and a file inside the root silent (no de-duplication, no file opened). No regular file other than an ignore-file candidate is opened; `WalkOptions::new` also refuses empty and whitespace-only excludes. An unreadable directory must still be `unreadable` (run the ignore-file check only when the directory can be listed).
3. Spec §7 and §15.

Nothing else changes: no command, no config, no schema. `src/core` stays untouched.

## Security call

Sensitive: run the security-reviewer (guarded paths `src/storage/`, `Cargo.toml`, `Cargo.lock`). It should probe: the dependency's provenance and licence; its regex size limits against hostile `.gitignore`/`.haliignore` patterns (ReDoS, huge globs, very long lines, many patterns); that `ignore` reads `~/.gitconfig` as text and never runs `git`; that no directory symlink is followed and the root can never be left (outside-root targets refused); races between the walk's `stat` and a later `inspect` (#115 is unchanged); that FIFOs and devices are never opened; deep trees and large directories; terminal escapes in file names are the caller's concern (the walker yields raw paths; #22 escapes them in output).

## Risks

`ignore`'s global-gitignore lookup depends on HOME and XDG_CONFIG_HOME, so tests must control them. A hostile `.gitignore` is read from the scanned tree, which is untrusted input. The crate's behaviour with `require_git(true)` and `parents(true)` across filesystem boundaries needs a test with a temp tree. `ignore` needs Rust 1.88 or newer (the toolchain is 1.99.1).
