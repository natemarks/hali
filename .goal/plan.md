## Approach

1. `src/ontology/mod.rs`: `owl::CLASS`, `rdfs::{SUB_CLASS_OF, LABEL}` constants.
2. `src/core/mod.rs`: `Error::{unknown_type, type_in_use, type_label_taken}`; move `fold`, `levenshtein` and the suggestion ranking out of `concept.rs` into one shared `pub(crate)` helper over candidate `(id, names, label)` (so #76's fix lands once); keep `shell_quote`; a shared helper for the "attach with `=` / after `--` when it starts with `-`" logic that `Error::in_use` and the `concept remove` retry build inline.
3. `src/core/types.rs` (new): `Type`, `valid_name`, `resolve`, `add`, `list`, `remove`. Types found with one fixed SPARQL query over the union default graph (`SELECT DISTINCT ?t WHERE { ?t a owl:Class ; rdfs:subClassOf+ hali:Resource FILTER(isIRI(?t) && ?t != hali:Resource) }`), `without_default_http_service_handler()`. A name is used if `hali:<Name>` appears as subject, predicate or object in any graph. Concept minting is unchanged (#38).
4. `src/core/resource.rs`: `add_all(ctx, store, files, title, types, tags, user)` (update the 5 existing callers); `Edit.{add_types, remove_types}` (Resources-graph quads, `held` filter as for tags); `Query.types` with `SELECT DISTINCT ?r WHERE { ?r rdf:type/rdfs:subClassOf* ?t }`, `?t` bound by `substitute_variable`, union default graph, results intersected like `tagged()`.
5. `src/cli/mod.rs`: `Command::Type(TypeCommand{Add{name, parent}, List{limit, offset}, Remove{reference}})`; `add --type`; `edit --add-type/--remove-type` added to the ArgGroup; `find --type`; generalise `concept_mutated` into a small vocabulary-mutated helper parameterised by the noun; confirmation as for `concept remove`; every stored id and label through `printable`.
6. Schemas: `type_add.json`, `type_list.json`, `type_remove.json`, `$defs/type`, the `UNKNOWN_TYPE` branch, `IN_USE`/`LABEL_TAKEN` as `anyOf`; `SCHEMAS` 14 → 17.
7. The implementer updates: `tests/cli_schema.rs`, `tests/core_schema.rs`, `cli_schema__schema_list_json.snap`, `tests/dry_run_guard.rs` rows, the `cli_dry_run` read-only list, and the existing `add_all` call sites.

Reuse: suggestion ranking, `apply`, `validate::guard`, `mutated()`, `confirm()`, the remove skeleton (node comparison, blank nodes counted, vocabulary-only, `changes []` means no prompt). Do NOT copy: slug minting with `-2` suffix (a Type name is the user's id; a clash is refused), `id_of` from `concept.rs` (use the `hali:`-prefix rule), the Concept scheme check, `TAGGED_*` with another predicate, `record()`'s Resources-graph reads for "a Type" (Types are read from any graph).

Cross-cutting: implementer on opus (split into (a) `type add|list|remove` + errors and (b) assignment and `find` if round 1 stalls).

## Security call

No listed security-sensitive path is touched (`save(File::Vocabulary)` exists). Security-reviewer recommended: `type remove` is destructive and reads stdin. Risks and covering checks: over-removal (byte comparison of resources.ttl and extensions.ttl); dangling `rdf:type`/`subClassOf` (`IN_USE` over every graph, blank nodes counted, nodes not ids); removing the root (`hali:Resource` refused for remove and add); a Type IRI colliding with a core shape or Concept (refused if used in any position); shell quoting (`=`/`--` forms plus quoting); terminal escapes (`printable`; UNKNOWN_TYPE text errors stay with #73); suggestion CPU cost (#76, shared helper); saving before confirmation (byte-equality); stdin hang (`remove_never_waits_on_stdin`).
