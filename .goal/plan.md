# Plan for #33: release pipeline and v0.1.0 readiness

Approved by the maintainer on 2026-11-18, with all eleven defaults. The contract (behaviour, refined acceptance criteria 1-16, safety rules, out of scope) is the "Groomed contract (approved)" section of issue #33; this plan adds the seams, the goal map and the approach.

**Safety rule (overrides everything):** no test, check or agent ever creates a real tag, push or GitHub release, or contacts GitHub. Scripts run only against a throwaway fixture repo with a local bare `origin`, with `GH` pointing at a fake `gh`. The real `release-prepare` / `release-publish` are never run, not even with `DRY_RUN=1`. The only run of real repo code is `make dist` inside a throwaway clone.

## Decisions (maintainer)

- License `MIT OR Apache-2.0`: `LICENSE-MIT` (`Copyright (c) 2026 Nate Marks`), `LICENSE-APACHE` (the unmodified Apache-2.0 text, copied byte-for-byte from the registry copy that most dependencies share, `sha256 a60eea81...`, e.g. `~/.cargo/registry/src/*/hashlink-0.10.0/LICENSE-APACHE`), `license = "MIT OR Apache-2.0"` in `Cargo.toml`, spec §16 updated. There is no single `LICENSE` file.
- dist before tag; resume on rerun, refuse when a release exists; v0.1.0 needs `## Benchmark results` in ADR-0001; versions in `[0.1.0, 1.0.0)`; `cargo-edit` pinned 0.13.14 (installed locally; CI `test-external` installs it); `jq` is a maintainer dependency; no root check in install.sh; README Install section; pre-commit stays on the bump commit; skill step guarded by `skill --help`.

## Seams

- **The scripts** are run by absolute path with `BUMP`, `DRY_RUN`, `GH` and `RELEASE_STATIC` set and cwd a throwaway fixture repo. The fixture is a no-dependency crate named `hali`, generated by the test from strings (no nested manifest is checked in): its main prints `hali <ver>` and fixed `generate man|completions` output, and a `test-hooks` feature adds a `HALI_TEST_` string. It has its own Makefile with `static-check`, both license files, an ADR, and `origin` = a local bare repo. `GH` points at `tests/fixtures/release/fake-gh`, which logs its arguments to a file and takes its answers from environment variables. Two network guards: a `gh` shim on `PATH` that exits 99, and git run with a temporary `HOME`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`. `CARGO_HOME` and `RUSTUP_HOME` are passed through.
- **install.sh** is run from a staged directory with a shell-stub `hali` and `HOME=$tmp`.
- **The Makefile**: `make help`, `make -n <target>`, `make shellcheck`.
- **The real repo**: a check only (`03-real-dist.sh` runs `make dist` in a local clone with a fixture license commit).

## Goal map

All `tests/release_{install,dist,flow}.rs` tests are goal-tagged (`#[cfg(feature = "goal")]` on its own line) and `#[ignore = "needs bash, git, tar, shellcheck, jq, cargo-edit (make test-external)"]`. Because `make goal-tests` skips ignored tests, `.goal/checks/01-release-tests.sh` runs them with `-- --ignored`. "spawn NotFound" means the script does not exist yet.

## Approach (for the implementer)

1. License files, `Cargo.toml` field, `.gitignore`.
2. `scripts/release-lib.sh`: the `run` helper (DRY_RUN printing, strict parsing), preflight functions, version reader.
3. `scripts/install.sh` and its tests (fast, stub binary); `shellcheck` target gains it at default severity.
4. `scripts/dist.sh` against the fixture crate, then the real-repo check.
5. `scripts/release-prepare.sh`, then `scripts/release-publish.sh` with its resume states.
6. Makefile targets, docs (spec §13.2-13.4 and §16, README Install, AGENTS.md command table and the "arrive with their tickets" sentence), CI `cargo install cargo-edit --locked --version 0.13.14` in the `test-external` job.

Opus implementer and reviewer; the security-reviewer is required. No `src/` changes.

## Risks

- `cargo set-version` may not update `Cargo.lock` as expected; a `--locked` assert after the bump catches it.
- The pre-commit hook makes the bump commit slow.
- Byte-identical tarballs hold only on the same machine.
- If `gh release view` fails, the script cannot tell "not found" from a network error; `release create` then fails safely.
- `SHA256SUMS` catches corruption, not a compromised GitHub account (signing is out of scope).
